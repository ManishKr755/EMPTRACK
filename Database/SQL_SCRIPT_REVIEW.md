# EMPTRACK SQL script review

This is a static review of the SQL source files shipped with EMPTRACK. No script was executed and no live database was contacted. Table names below use the existing singular dbo names from the scripts and EF Core mapping.

| Script | Purpose / objects | Idempotency and data effects | Risk / notes |
|---|---|---|---|
| `02_CreateTables.sql` | Creates Employee, UserAccount, Department, Team, Attendance, LeaveType, LeaveBalance, LeaveRequest, Task, PerformanceReview, SalaryPayment, Notification, Announcement, Holiday, Concern, and ConcernMessage tables. | Not idempotent; creates tables and initial keys/unique constraints. No seed data. | Must be used only for a fresh database; rerunning fails if tables exist. It is not an upgrade migration. |
| `03_AddForeignKeysAndConstraints.sql` | Adds foreign keys between accounts/employees, employees/teams/departments, teams/departments/managers, department heads, attendance, leave, tasks, reviews, salary, notifications, announcements, holidays, and concerns/messages; adds unique indexes including one account per employee, one attendance per employee/date, and one balance per employee/leave type. | Most operations check for existing named constraints/indexes first. Adds referential integrity and uniqueness. | Existing orphan/duplicate data can make additions fail. Review actual schema and data first. |
| `06_TestData.sql` | Seeds sample departments, employees, accounts, teams, and related test/demo records; updates department head assignments and related setup. | Uses `IF NOT EXISTS` for many inserts and includes updates to existing setup records. | Intended for a demo/test database only. Inspect each insert/update before use on any database with real data. Password values and sample PII should not be used as real credentials/data. |
| `07_UpdateLeaveTypeAllocation.sql` | Adds/updates leave type allocation columns and allocation values. | Uses column/constraint existence checks for schema setup and updates allocation data. | Review existing allocations before applying; allocation updates can affect future balance calculations. |
| `08_ApproveLeaveRequest.sql` | Creates/updates `dbo.ApproveLeaveRequest`; locks pending requests and balance rows, validates status and sufficient balance, deducts once, and marks approved in a transaction. | Uses `CREATE OR ALTER PROCEDURE`; no table drops. | Requires schema and balance rows expected by the procedure. The app checks role/scope before invoking it. Do not bypass the controller authorization by exposing the procedure directly. Calendar-day counting is used; holiday/weekend exclusion is not implemented in this procedure. |
| `09_AddPasswordManagement.sql` | Adds `EncryptedPassword` and unique one-account-per-employee index when absent. | Column/index checks make it mostly idempotent. It can fail if duplicate employee accounts exist. | Reversible password protection is retained for legacy compatibility but should not be exposed in UI or logs. |
| `11_CreateInitialAdmin.sql` | Creates or updates the `admin` account. | Insert/update based on username. The revised script requires an operator-provided ASP.NET Core password hash; no default password is included. | Updating an existing `admin` row resets its password and reactivates it. Review carefully before use. Do not run with the placeholder hash. |
| `12_DropAuditLog.sql` | Drops `dbo.AuditLog` if it exists. | Conditional but destructive. | Do not execute without explicit approval and a separate backup/retention decision. It removes the table and its contents. |
| `13_AutomaticLeaveBalanceAccrual.sql` | Adds `LeaveBalance.LastAccruedPeriod` if absent and initializes existing balances to the current allocation period. | Column addition is guarded; data update affects existing balances with null tracking values. | Existing balances are preserved, but the period marker changes accrual behavior. Apply manually after review. |
| `14_AnnouncementAudience.sql` | Adds `Announcement.AudienceType` and nullable `DepartmentId`, department FK, and audience check constraint. | Guards column/constraint additions. Existing announcements receive `AllExceptAdmin` through a default/backfill. | Run before deploying the model/controller that references the columns. Confirm schema/table/constraint names against the target database. No announcement rows are deleted. |
| `15_HolidayDateUniqueConstraint.sql` | Adds a unique index on `Holiday.Date`. | Checks for duplicate dates and throws before adding the index; guarded index creation. | If duplicates exist, resolve them manually and preserve any required history. This script does not delete or merge rows. |

## Recommended manual execution order

For a fresh demo database, follow the project's established setup instructions: create tables (`02`), add constraints (`03`), apply the applicable allocation/password/admin/accrual scripts (`07`, `09`, `11`, `13`), seed demo data only when appropriate (`06`), and install/update the approval procedure (`08`). Apply `14` and `15` only when deploying the corresponding updated application code and after checking prerequisites. This is a review order, not an instruction to execute these scripts automatically.

`12_DropAuditLog.sql` is intentionally excluded from the normal setup sequence. None of these scripts was run as part of the code task.
